## Reproducible harness

The [Android generator](../../tool/companion_live_probe/android-prepare-harness.sh)
uses the pinned Flutter SDK, the
[resolved package lock](../../tool/companion_live_probe/android-pubspec.lock),
and the platform-neutral
[native harness](../../tool/companion_live_probe/ios-native-main.dart).
The `ios-` prefix identifies its original spike ownership; the same Dart code
runs on both native platforms. No test private key is checked in. Preparation
creates an ephemeral certificate for loopback-only test traffic.

The harness invokes the unchanged production-independent P0 `beginCapture`
operation. Its ordinary public request uses system HTTPS trust. Local tests
redirect their own connections to an in-app TLS server and trust only the
generated test certificate in that scope. This exception does not affect the
public request or device trust stores.

Candidate plugins are exactly `sqflite 2.4.4+2`, `path_provider 2.1.6`, and
`flutter_timezone 5.1.1`. The smoke test looks up documents/cache/temporary
directories and the native IANA zone, then creates a small SQLite table,
commits a transaction, closes/reopens the database, verifies its row and removes
the test database. It does not implement application persistence or migrations.

### Build provisioning findings

The shared SDK contains Android platforms 34, 36 and 36.1. The first build
failed because `flutter_timezone 5.1.1` explicitly compiles against API 35.
`android.builder.sdkDownload=false` prevented an implicit shared SDK change.
API 35 is a compile dependency; it is not the application's minimum OS.

The final shell uses `work/p0-android/sdk/`. Existing API 36, NDK 28.2, build
tools 36.0.0, platform tools, CMake 3.22.1 and accepted SDK license files were
copied there; only API 35 revision 2 was downloaded into that local SDK.
An intermediate isolated build also identified the missing CMake copy, which
was then supplied from the existing installation. No plugin source or shared
SDK version was changed to resolve either provisioning issue.

The emulator's initial sandbox invocation reported a Qt NEON detection failure.
The same installed executable worked with approved native process access.
That sandbox failure is not an emulator or application compatibility defect.

## Running another bounded check

Use a new project directory. Set `ANDROID_HOME` to an SDK with API 35 and 36,
build tools 36.0.0, NDK 28.2.13676358 and CMake 3.22.1 provisioned. Set
`PUB_CACHE` and `GRADLE_USER_HOME` to disposable workspace directories.

```sh
export FLUTTER_BIN=/Users/chris/flutter/bin/flutter
export PUB_CACHE="$PWD/work/pub-cache"
export GRADLE_USER_HOME="$PWD/work/p0-android/gradle-home"
export ANDROID_HOME="$PWD/work/p0-android/sdk"
export ANDROID_USER_HOME="$PWD/work/p0-android/android-user-home"
sh tool/companion_live_probe/android-prepare-harness.sh \
  "$PWD/work/p0-android/native-app"
```

Build from that generated project. Only the following explicitly enabled build
makes a public request, once per fresh process launch. To repeat local checks
without further source traffic, omit `RUN_PUBLIC_CAPTURE=true`.

```sh
"$FLUTTER_BIN" build apk --debug --target-platform android-arm64 --no-pub \
  --dart-define=RUN_PUBLIC_CAPTURE=true \
  --dart-define=LEAGUE=uefa.champions \
  --dart-define=SCOREBOARD_DATE=20261020
```

From the repository root, create a dedicated AVD from the installed shared
system image. Keep the build SDK and the device-tool SDK distinct:

```sh
export ANDROID_DEVICE_TOOLS=/Users/chris/Library/Android/sdk
export ANDROID_AVD_HOME="$PWD/work/p0-android/avd"
export ANDROID_EMULATOR_HOME="$PWD/work/p0-android/emulator"
export ANDROID_ADB_SERVER_PORT=5038
env ANDROID_HOME="$ANDROID_DEVICE_TOOLS" \
  "$ANDROID_DEVICE_TOOLS/cmdline-tools/latest/bin/avdmanager" create avd \
  --name soccer_p0_api36_1 \
  --package 'system-images;android-36.1;google_apis_playstore;arm64-v8a' \
  --path "$ANDROID_AVD_HOME/soccer_p0_api36_1.avd" --device pixel_7
"$ANDROID_DEVICE_TOOLS/platform-tools/adb" -P 5038 start-server
env ANDROID_HOME="$ANDROID_DEVICE_TOOLS" \
  "$ANDROID_DEVICE_TOOLS/emulator/emulator" \
  -avd soccer_p0_api36_1 -port 5580 -no-window -no-audio \
  -no-snapshot -no-boot-anim -gpu swiftshader \
  -camera-back none -camera-front none
```

Install only on that explicitly selected emulator, then run the
[Android controller](../../tool/companion_live_probe/android-run-harness.py)
from the repository root:

```sh
"$ANDROID_DEVICE_TOOLS/platform-tools/adb" -P 5038 -s emulator-5580 install \
  work/p0-android/native-app/build/app/outputs/flutter-apk/app-debug.apk
work/companion-venv/bin/python tool/companion_live_probe/android-run-harness.py \
  --adb /Users/chris/Library/Android/sdk/platform-tools/adb \
  --require-public-capture \
  --output work/p0-android/native-run.jsonl
```

The controller verifies the exact AVD identity before acting, backgrounds the
app only after its stalled lifecycle request reaches the local server, waits
three seconds, and brings the same app back. It retains structured probe
records and rejects failed or missing checks. Completion of local checks alone
does not prove public HTTPS success. Omit `--require-public-capture` for an
intentionally local-only build.

Stop this emulator with `adb -P 5038 -s emulator-5580 emu kill`, then stop only
its alternate adb server with `adb -P 5038 kill-server`. No app signing account,
release, publication or persistent device configuration is required.

The recorded emulator, alternate adb server and workspace Gradle daemon were
stopped after verification. Generated shells, local SDK and raw logs remain
under ignored `work/p0-android/`.

## Remaining limits

This debug emulator result establishes native Android transport and the selected
plugin calls on the recorded API 36 image. It does not establish minimum-API-24
runtime behavior, physical-phone or tablet performance, release compilation,
background scheduling, force-kill/crash durability, persistence migrations, or
source licensing. Late-response rejection after an obsolete operation completes
with data is covered separately by deterministic session tests; this native
lifecycle test cancels a genuinely stalled connection.

No production polling was enabled. Source permission, score freshness policy,
identity/kickoff reconciliation and authoritative corrections remain separate
distribution or later-stage gates.
