# P0 ownership and requirement inventory

Historical baseline: the P2 [route/calendar migration](p2-evidence.md),
[viewer-eligibility migration](p2-eligibility-evidence.md),
[route-validity acceptance](p2-validity-evidence.md),
[fixture-window acceptance](p2-window-evidence.md),
[status/result review checkpoint](p2-status-evidence.md) and
[rule catalog](rules/README.md) name the shared owners now implemented. The table
below preserves the original inspection; its JavaScript/Python owners are
superseded only for the migrated decisions named in those records.

`evaluateFixtureWindow` now owns browser `inFocus`/`bucketOf` decisions and
composed `buildOutlook` window membership. The `fixture_window` bridge operation
also has a Python adapter. `decodeEspnStatus` and `decodeFixtureStatus` now own
the bounded status/result mapping in pure data code, consumed through the CLI
and browser bridge. Source-observation freshness and the separate Python
static/AI windows remain with their existing owners pending their own migrations.

This inventory records the existing implementation at `9b977bb` and the proposed destinations in the [architecture](architecture.md). It is the ownership portion of [P0](implementation-plan.md#p0-prove-the-architecture), reviewed on October 20, 2026. It does not mark P0 complete or claim that the proposed Dart, application, data or mobile owners already implement these requirements.

The evidence below is source and test inspection. A named existing test means that the repository contains that check; it is not a claim that the test was executed for this inventory or that it proves the whole companion requirement. The new-client checks in the last column are future work. Captures, bridge measurements, native transport evidence and schema validation have separate deliverables.

## Current production rule inventory

### Published facts and the default view

1. **Source facts and identity** remain publisher-owned. Build `fetch_scoreboards`, `_scoreboard_scope_error`, `interpret_all` and `interpret` acquire/normalize ESPN events, skip explicit excluded rounds, preserve read failures and establish teams/competition/kickoff. Broadcaster adapters enrich these facts; AI must not modify them. The proposed exporter must preserve identity and uncertainty before filtering.
2. **Rights and package facts** are authored in `rights.toml` and loaded by `load_rights`. Build `map_outlet`, `usual_home` and `league_hint` resolve aliases, competition-specific access and season-limited usual rights. `provider_utils.confirm` adds only recognized explicit channels and clears a superseded usual rule. These mappings stay Python-owned; clients receive explicit routes rather than remapping network names.
3. **Retained evidence** is selected by `broadcast_listings.retain_recent_evidence`. It requires the same fixture, league, kickoff and teams; pre/in status; less than four hours after kickoff; US match-listing evidence with HTTPS source and original `checked_at`; at most six hours of age; and a permitted outage/incomplete-source reason. It does not overwrite a clean rejection, invent missing source checks or renew the original time. Publisher retention remains factual acquisition behavior; the core additionally enforces the published absolute validity limit between refreshes.
4. **Default viewer eligibility is duplicated.** Build `evaluate` selects a listed outlet before a usual rule. Within listed outlets it orders by `SERVICE_RANK`, prefers an outlet named as the service itself, then English over Spanish. App `evaluateRow` repeats this using saved service order (`rankOf`), the same outlet-name preference and language preference. `passes`/`editorialPasses` then apply league choice/temporary hiding. Core must own this selection once, including the publisher's explicit default preferences.
5. **`evaluate` has more consumers than the main page.** Build `interpret`, `provider_utils.confirm` and retained-evidence restoration assign `Match.service/basis/outlet`; `row_html` and `build_page` render/count them; `write_facts` uses them for watch descriptions; `metrics.snapshot` records the default projection; `discovery._coverage` invokes `evaluate` for a service-specific public page. A CLI integration that changes only the main page would leave production duplicates or stale derived answers.
6. **Default league/window decisions also exist in Python.** `shown_by_default` reads `LEAGUES[*].default_off`. `build_page` counts non-final/default-enabled fixtures from `built_at - 125 minutes` to `story_state.window_end`; its static day sections group by Eastern calendar date, while App regroups by local 4 a.m. sports day. `tables_html` uses `window_end` for table shading. `discovery.sports_day` has another 4 a.m. implementation for public discovery pages. Keep publisher fetch conventions separate from viewer-local decisions, and name the migration boundary for each consumer.
7. **Facts are not synonymous with the default view.** `write_facts` supplies service-backed editorial candidates independently of owner selection, all eligible ranking candidates, the default league metadata and base score inputs. `schedule_data.publish` currently writes rendered HTML rows and runtime revision, not the proposed factual companion contract. Neither the current HTML feed nor `schedule-context.json` should become the native model.

## Application and persistence gaps

The site provides useful prior evidence but not the full proposed native lifecycle:

- Ordinary browser preferences use several localStorage keys and silently ignore `write` failures. Personal AI uses one record and reports `notSaved`, but applies in memory before its persistence attempt. Native application commands need the specified atomic, durable success semantics; this is new behavior to prove, not a browser pattern to copy unchanged.
- Schedule refresh validates the current HTML feed before DOM replacement and preserves old rows on failure. It is not the transactional downloaded snapshot cache, compatibility/integrity envelope, or offline cold-start path required by DATA-1.
- Live transport has a one-minute cadence, fifteen-minute lead, four-hour normal tail, thirty-hour catch-up limit, eight-second request timeout and bounded backoff. Schedule transport checks every five minutes with its own timeout/backoff. These are present browser policy baselines; move them to named policy owners before sharing them. [P0 transport evidence](p0-live.md) now demonstrates bounded native access; source permission remains a distribution gate.
- Browser live batches are invalidated on navigation, but fixture generation/identity/kickoff reconciliation is incomplete for the proposed data model. `applySchedule` checks league and displayed names before preserving a newer overlay, not kickoff equality or source observation revision. Native out-of-order and correction tests remain necessary.
- Browser card DOM sharing is evidence for content consistency, not a reusable Flutter model. Native text measurement, accessible actions, calendar draft confirmation, cloud backup exclusions and physical-device verification have no current native owner.
- The maintainer's GitHub shared-publication workflow is outside first-release native scope. A browser-local response or owner token must not be transferred into the mobile app or public factual feed as an implementation convenience.
